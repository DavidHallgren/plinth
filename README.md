# Plinth

Plinth is a local-first screenshot composition studio. Phase 3 adds a usable asset/device workflow to the JSON-backed Konva editor: validated local image files, an asset library, real image elements, vector device frames, screenshot clipping, selection, transforms, undo/redo, and debounced autosave stay readable and local.

## Requirements

- Bun 1.3 or newer
- A modern browser

Install dependencies and start the development server:

```sh
bun install
bun run dev
```

Open [http://localhost:3000](http://localhost:3000). The starter project lives at `data/projects/plinth-starter/`.

Set `PLINTH_DATA_ROOT` when a script or test needs an alternate local project directory:

```sh
PLINTH_DATA_ROOT=/tmp/plinth-projects bun run tool list --json
```

## Scripts

| Script | Purpose |
| --- | --- |
| `bun run dev` | Start the hot Bun server |
| `bun run start` | Start the server without hot reload |
| `bun run build` | Build the standalone `dist/plinth` executable |
| `bun run test` | Run schema, migration, storage, preset, scene, and history tests |
| `bun run typecheck` | Run strict TypeScript validation |
| `bun run check` | Run typecheck and tests |
| `bun run tool help` | Show CLI commands |

Tailwind 4 styles are generated by lifecycle hooks into the ignored `src/styles.generated.css` file. Restart the dev server after changing `src/styles.css`.

## Editor model

- `src/lib/schema.ts`, `src/lib/migrations.ts`, and `src/lib/defaults.ts` are the persisted data boundary. Schema v3 adds canonical asset paths, normalized image fit/focal settings, and data-driven device properties while preserving v0-v2 migrations.
- `src/scene/operations.ts` contains immutable document/layer operations. It maintains positive dimensions, bounded transforms, fresh IDs, and contiguous z-order.
- `src/lib/asset-validation.ts` owns independently testable path, signature, dimension, size, SVG-safety, naming, and hashing checks. `src/lib/storage.ts` is the file-backed asset transaction boundary; it validates before writing, de-duplicates by content hash, and protects referenced deletion.
- `src/scene/history.ts` is a 100-entry operation history. `EditorStore` keeps selection, zoom, clipboard, and transactions outside project JSON; pointer gestures commit as one history entry.
- `src/canvas/scene-renderer.tsx` is the shared Konva scene-rendering boundary used by the active editor and lightweight document thumbnails. `src/canvas/image-loading.tsx` provides the reusable image-loading/error boundary without base64 or permanent object URLs.
- `src/devices/presets.ts` and `src/devices/geometry.ts` contain data-driven device presets and pure screen/fit calculations. Apple iPhone 17 Pro/Pro Max geometry context comes from the official [technical specifications](https://www.apple.com/iphone-17-pro/specs/); frames are normalized vector geometry, not third-party artwork.
- `src/components/editor`, `src/components/sidebar`, and `src/components/toolbar` compose the editor surface from small UI primitives.

## App Store document presets

The editor exposes the requested portrait presets: 1320×2868, 1290×2796, 1284×2778, 1242×2208, 2064×2752, and Custom. Apple currently groups these across iPhone 6.9-inch/6.5-inch/5.5-inch fallback groups and the 13-inch iPad group; the presets intentionally keep each source size editable. See Apple’s [current screenshot specifications](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications/) before export validation is implemented.

## CLI

The CLI shares schema and storage with the app:

```sh
bun run tool list
bun run tool validate plinth-starter
bun run tool inspect plinth-starter --json
bun run tool add-document plinth-starter iphone-6-9 "Launch frame"
bun run tool duplicate plinth-starter plinth-copy
bun run tool rename plinth-copy "Plinth copy"
bun run tool delete plinth-copy --yes
```

`export` remains an explicit reserved boundary until the later rendering/export phase. Asset routes are available for the editor and future clients:

- `GET/POST /api/projects/:slug/assets` lists metadata or accepts a multipart `file` upload.
- `GET/DELETE /api/projects/:slug/assets/:assetName` serves or removes one registered asset. Deletion returns structured usage details and requires an explicit `force=true` request to remove referenced files.

Uploads accept PNG, JPEG, WebP, and conservatively validated SVG, with a 25 MB limit. Project JSON stores only metadata and project-relative paths such as `assets/hero-a1b2c3.png`; image bytes remain in the project `assets/` directory.

## Project format

Each project directory contains a pretty-printed `project.json`, an `assets/` directory for binary files, and an `exports/` directory. JSON writes are validated and atomic. Binary image data never belongs in `project.json`; asset metadata includes a stable id/path, file name, MIME, dimensions, byte size, and content hash. Stored bytes are revalidated when served so an unsafe manual SVG replacement fails with an actionable structured error.

Unversioned and schema v1/v2 projects migrate to schema v3 on load. Future versions fail clearly instead of being silently discarded.

## Phase 3/4 boundaries

Phase 4 intentionally defers final PNG export, the export dialog/download and all-document progress UI, CLI export behavior, final keyboard/error/loading polish, full text auto-height, true drag-to-reorder, and comprehensive README/AGENTS refinement. The shared scene renderer and normalized asset/device paths are the extension points for that work.
