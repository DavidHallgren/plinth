# Plinth

Plinth is a local-first screenshot composition studio. Phase 2 adds a practical Konva editor on top of the Phase 1 JSON-backed project and API boundary: documents, layers, text, shapes, gradients, selection, transforms, undo/redo, and debounced autosave stay readable and local.

## Requirements

- Bun 1.3 or newer
- A modern browser

Install dependencies and start the development server:

```sh
bun install
bun run dev
```

Open [http://localhost:3000](http://localhost:3000). The starter project lives at `data/projects/plinth-starter/`.

Set `PLINTH_DATA_ROOT` when a script or test needs an alternate local project directory:

```sh
PLINTH_DATA_ROOT=/tmp/plinth-projects bun run tool list --json
```

## Scripts

| Script | Purpose |
| --- | --- |
| `bun run dev` | Start the hot Bun server |
| `bun run start` | Start the server without hot reload |
| `bun run build` | Build the standalone `dist/plinth` executable |
| `bun run test` | Run schema, migration, storage, preset, scene, and history tests |
| `bun run typecheck` | Run strict TypeScript validation |
| `bun run check` | Run typecheck and tests |
| `bun run tool help` | Show CLI commands |

Tailwind 4 styles are generated by lifecycle hooks into the ignored `src/styles.generated.css` file. Restart the dev server after changing `src/styles.css`.

## Editor model

- `src/lib/schema.ts`, `src/lib/migrations.ts`, and `src/lib/defaults.ts` are the persisted data boundary. Schema v2 adds normalized gradient definitions, text controls, shadows, and App Store document presets.
- `src/scene/operations.ts` contains immutable document/layer operations. It maintains positive dimensions, bounded transforms, fresh IDs, and contiguous z-order.
- `src/scene/history.ts` is a 100-entry operation history. `EditorStore` keeps selection, zoom, clipboard, and transactions outside project JSON; pointer gestures commit as one history entry.
- `src/canvas/editor-canvas.tsx` is the Konva rendering boundary. Only the active full-resolution document is mounted.
- `src/components/editor`, `src/components/sidebar`, and `src/components/toolbar` compose the editor surface from small UI primitives.

## App Store document presets

The editor exposes the requested portrait presets: 1320×2868, 1290×2796, 1284×2778, 1242×2208, 2064×2752, and Custom. Apple currently groups these across iPhone 6.9-inch/6.5-inch/5.5-inch fallback groups and the 13-inch iPad group; the presets intentionally keep each source size editable. See Apple’s [current screenshot specifications](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications/) before export validation is implemented.

## CLI

The CLI shares schema and storage with the app:

```sh
bun run tool list
bun run tool validate plinth-starter
bun run tool inspect plinth-starter --json
bun run tool add-document plinth-starter iphone-6-9 "Launch frame"
bun run tool duplicate plinth-starter plinth-copy
bun run tool rename plinth-copy "Plinth copy"
bun run tool delete plinth-copy --yes
```

`export` and asset routes remain explicit reserved boundaries until the browser renderer and asset ingestion phases.

## Project format

Each project directory contains a pretty-printed `project.json`, an `assets/` directory for binary files, and an `exports/` directory. JSON writes are validated and atomic. Binary image data never belongs in `project.json`; the Phase 2 starter uses device and asset placeholders rather than embedded image content.

Unversioned and schema v1 projects migrate to schema v2 on load. Future versions fail clearly instead of being silently discarded.

## Phase 3/4 boundaries

Asset upload/ingestion, real device image clipping, browser screenshot rendering/export, and production export validation are intentionally deferred. The editor’s image branch remains a clean placeholder so those capabilities can be added without changing the scene operation contract.
